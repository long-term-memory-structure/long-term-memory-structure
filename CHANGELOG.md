# Changes

## 0.1.0 (2026-11-09)

- `ltms search <query> <path>...`: finds the turns that hold every word of a query, in the transcripts named and in every `.jsonl` under the directories named. It prints addresses, key paths and offsets, never the text. The coverage line comes first (what was searched, what was not, every count). Then come the files with a hit, newest session first, each with its matching turns: at most `--max` turns (20; `0` for all), after the first `--skip` (0). The coverage's `shown` counts the matching turns passed over (`skipped`) and printed (`turns`), and `left` those after the ones printed, so `skipped + turns + left = hits.turns`; `next` is the command that prints the next ones (`--skip` past those printed, with the same `--max`). Options: `--kind <list>` (default: all but meta and attachment), `--substring`, `--max`, `--skip`, `--count`, `--oldest`. Exit 0; 1 when a file or a directory could not be read, or was too large; 2 on a usage error.
- search's closing line, on stderr, counts the matching turns and the files that hold them, out of the files found. For `ltms search --max 3 test` on a demo project's 35 transcripts: `ltms search: 173 matching turns in 35 of 35 files (35 read, 0 failed); 3 shown, 170 left: --skip 3 shows the next 3.`
- search refuses with the reason and the next command: no path (it names the current directory's project folder, or says that the current directory no longer exists), an unknown kind, a query with no word, and the query and the paths in the wrong order: a path that does not exist and looks like a word, or a query that names an existing path (one with a `/`, or ending in `.jsonl`) when no path argument names one (the query was left out). When a path argument does name one, such a query is searched, with a notice that gives the command for the other reading. Every command a message gives puts `--` before a query or a path that starts with `-`, so it runs as given.
- search's notices go to stderr. A query holding Hebrew, Arabic, Korean or spaceless-script letters draws one with the `--substring` command. `--substring` draws one for every query, each term echoed, saying what it costs: it also finds words that only contain them, as `cat` finds `concatenate` (the coverage's `mode` row says so too). A Node without `Intl` cannot run the search, and says so (exit 2); skeleton, stats and pin do not need it.
- search: a hit's `field` names keys down to a tool's parameter (the first level of its input), a system record's own keys and an attachment object's own keys, each by the label rule. A key below them is data a tool or the model wrote, and prints `(withheld)` even when it passes the label rule; an array counts as a level. Where `field` holds `(withheld)`, the window command in the help and the README prints the keys at that place whose value leads, along the rest of `field`, to a string longer than `at`, so one can be put in; where `field` leads to no string, or to one no longer than `at`, it says so (`not a string here`, `at is past the end of this field`), never with an empty line or a stack trace. The `system` kind reads every string of a system record but its envelope, its `subtype` and its `level`, which are names from a fixed list.
- search, under a directory: symbolic links are not followed, and each directory is read once, known by its device and inode (a bind mount of a directory inside itself would have its files read twice; tested on Linux, in a user namespace and with a stubbed `stat`, not on macOS or Windows). One warning line counts the files with nothing to search, the symbolic links, the entries named `.jsonl` that are not regular files (a pipe, a socket), the directories met again, and the files with warnings of their own; it names up to four of the latter, each with its kinds (lines that could not be read, records on a parentUuid cycle, responses read from parent links), and ends with the command that shows them.
- search: a file or a directory whose name is not valid UTF-8 is reported as such, with the name's bytes written as `\xHH`, and counted as failed. An internal error outside any one file is reported by its kind and its place in ltms, never its message (exit 1).
- search skips a file larger than a tenth of Node's heap limit (about 210 MB by default) and gives the command that gives Node more memory: running out of memory would end the search with every hit lost.
- `ltms pin <path>... --to <dir>` keeps copies of the transcripts that Claude Code's cleanup deletes (after `cleanupPeriodDays`, 30 days by default). It copies the cleanup's own shape (a project's `<name>.jsonl`, its set-aside copies, and the files under a session's `subagents/`, `tool-results/`, `workflows/` and `mcp-tasks/`) into a directory of your own, with `PINS.log`, a hash-chained log of every version. A rewritten file's old copy is kept by a hard link. Options: `--list`, `--rehash`, `--root`. `--from-hook` reads a Claude Code hook's JSON from standard input (a `SessionEnd` hook). `--check <dir>` reads every logged version back from its copy, checks the chain, and counts the sources the pin is missing or holds shorter. The library is the new `./pin` entry (`pinPaths`, `checkPin`, `claudeConfigDir`, `isSweepShaped`).
- pin's coverage line counts the files by outcome, `seen` = `new` + `grown` + `rewritten` + `unchanged` + `notCopied` + `failed` (`notCopied`: a `.jsonl` with no new line yet; `failed`: a source file that could not be read, kept or written), and `failures` counts every failure line. `--rehash` reads every file, and also each copy whose source still holds the version its last line records, writing it again from that source when it holds other bytes, whatever its size: recovery leaves to it a copy that no longer holds that version at its start, when no kept copy waits beside it. `--check`'s mismatch line names the copy read (`copy`). After a mismatch in a current copy whose source is there (under the root PINS.log records, as a regular file of the cleanup's shape reached through no symbolic link), its closing line gives the `--rehash` command for the projects of those copies, saying that it writes back what the sources still hold and that `--check`, run again, says what remains. While `PINS.log` has another name, `--check` says so, with the `find` command, and gives no pin command. `--check` counts apart (`unfinished`), with no command, a `.jsonl` whose copy is a byte prefix of it and which is longer only by an unfinished line, since a pin copies whole lines only; one rewritten under an unfinished line counts as longer. When the root itself cannot be read, `--check` names it, with its error code. A copy missing from the pin while its source has been rewritten cannot be kept, and a notice says that its version is lost.
- pin refuses, with the reason and the next command, before it writes anything (exit 2): no `--to`; a `--to` inside Claude Code's config directory, inside a path given or inside the root; a path inside `--to`; a path outside the root (for a symbolic link leading out of it, the message names where it leads and the command that pins it into a pin of its own); a `--to` that is not a directory, or that holds files and no `PINS.log` (pin never writes among files it did not make); a `PINS.log` that is a symbolic link, is not a regular file, or has another name (a hard link, under which every line appended later could be read); and a root other than the one PINS.log records (the `--root` command is given only when every path is under that root). pin writes through no symbolic link inside the pin directory: a file whose copy would go through one is a failure, `symlink-in-pin`. `PINS.log`, the lock and a kept copy are read and appended to only as regular files, so a symbolic link at one of those names is never read or written through, and a FIFO there is never waited on (a failure, `not-a-regular-file`; `PINS.log`, before a pin starts, is refused). `--check` reads a copy that is not a regular file as missing, and does not wait on a lock that is not one. For a `PINS.log` or a lock that is not a regular file, and for a `PINS.log` that cannot be read, the next command is `ls -l` on it (in `--check`'s refusal and pin's, `--check`'s notice on the lock, and a pin's closing line after the failure at the lock). While the pin directory is open to group or others, each run says so, with the `chmod 700` command, and says that whoever it lets write into it can replace pin's files.
- pin: a lock keeps two pins apart. Another pin waits for it up to 30 s, then exits 1, naming the holder and the `rm` command, and `--check` waits for a running pin the same way, since a file it is writing would read as damage. SIGINT, SIGTERM or SIGHUP stop a pin between two files, or while it waits for the lock, and it removes the lock.
- `ltms --help` gains a usage line for search and one for pin, and after the stats fields a paragraph for each, pointing to `ltms search --help` and `ltms pin --help`, which print each command's own part. Two of its sentences change: "Claude Code only appends to it" reads "Claude Code appends to it (it can rewrite one only in rare cases, and pin keeps both versions)", and the one on what ltms reads and writes names search's walk (every `.jsonl` file under the directories it is given) and pin's (the files under the paths it is given; it writes only into its `--to` directory). Every other word of 0.0.5's help is kept. The unknown-command message names search and pin.
- The Bash verb at its limit (a5, a6): a 16th command passed over with nothing after it but blank lines, comment lines and an opening `(`, `{` or `!` now gets what a shorter command gets (`(empty)`, or the first substitution's program) instead of `(withheld)`. A command that ends in a dangling `&&`, `||`, `|` or `|&`, with nothing after it but blanks, new lines, line continuations and comment lines, is `(withheld)` at any count, since bash rejects it (0.0.5 printed a program there). On 109,107 Bash calls of our own sessions no verb changes.
- The parser is now the package's library: `import { parseTranscript, repairedLivePath, turnsOf } from 'long-term-memory-structure'`. package.json gains main, types, an exports map ('.', './pin', and every path 0.0.5 resolved, checked against 0.0.5's own tarball, by import and by require, on Node 20.20, 22.23 and 26.12) and typesVersions, so that TypeScript's node10 resolution finds ./pin's types too: both entry points type-check under node10, node16, nodenext and bundler resolution.
- `repairedLivePath().bridges` is in path order, the earliest first, as `compactions` is; 0.0.5's `dist/parser.js` gave the latest first, the order in which the walk back from the head met them. No command's output depends on that order.
- Type declarations ship in dist/*.d.ts. The 9 member comments that were written with // are JSDoc, so the declarations carry them. A member the code can leave undefined is declared so (ApiRequest.timestamp, ToolCall.id and ToolCall.name are `string | undefined`), and `caller` (ToolUseBlock, ToolCall) is `unknown`: Claude Code 2.1.319 writes an object there, `{"type":"direct"}`. TranscriptStats.inputTurns' JSDoc names every input channel it counts.
- Library: search, as functions over strings with no Node imports (`src/search.ts`): `parseSearchQuery`, `searchTranscript`, `tokenizeForSearch`, `normalizeForSearch` and `checkSearchSupport`, their types, and `SEARCH_KINDS`, `SEARCH_DEFAULT_KINDS` and `SEARCH_GAP_SCRIPTS`. A turn's records are the ones `ltms skeleton` shows for it, including the call and result records of its calls wherever they sit, and the records before the first prompt are T001's. A record's text is read in nine kinds; `meta` and `attachment` (the harness's own text) only when named. A string that holds JSON escapes is read as written and decoded. Everything not read is counted, and in every file the records parsed = searched + offPath + replays + beforeFirstTurn + sidecars + kindsOff. A hit's `field` and the `system` kind follow the rules above. The results hold no transcript text but the query's terms, the field keys and the channel that pass the label rule, and `SearchResult.last`, the latest timestamp as the transcript holds it, unchecked.
- Library: one function reads both the query and the text. A run of a spaceless script is split by `Intl.Segmenter` on its NFC text before any mark is removed; then NFKD, lower case, final sigma to sigma, U+200B as a break, marks, format characters and U+0640 removed, NFC; then runs of letters and digits, cut between two adjacent letters of different scripts. On the scouts' 120 known queries, words mode does not find 27 (3 of them emoji, which read as nothing) and `--substring` 9.
- Library: a second entry point, `long-term-memory-structure/pin`, with `pinPaths`, `checkPin`, `claudeConfigDir` (Claude Code's config directory by its rule: `$CLAUDE_CONFIG_DIR`, else `~/.claude`, an empty one counting as unset; the command's search and pin read it there) and `isSweepShaped` (the cleanup's shape, which pin copies, as one rule). It keeps copies of Claude Code's transcripts that its cleanup does not sweep, in a directory you choose, with a log of every version, `PINS.log`, each line chained to the one before it. This entry point reads and writes files; the parser's entry point still imports nothing from Node.
- Library: `pinPaths` copies the cleanup sweep's own shape. Under each project directory that is `<session>.jsonl`, `<session>.jsonl.superseded-*`, and every file under a session's `subagents/`, `tool-results/`, `workflows/` and `mcp-tasks/`; anything else under the given paths is counted, not copied. A `.jsonl` is copied up to its last new line, and not at all before its first (`notCopied`). Each file is read once, and its copy is written from the bytes that were hashed, through a temp file, fsync and rename, with the source's mtime. A file with the same size and the same mtime, to the nanosecond, is not read again, unless `rehash` is set; with it, recovery leaves to the run a copy that no longer holds its version, beside which no kept copy waits, when its source, pinned in that run, still holds that version, so the run writes it again from the source. A rewritten file's old copy is kept by a hard link named by the sha256 of its bytes. Copies and the log are written 0600 (or the source's mode, when stricter), directories 0700. Nothing is written through a symbolic link inside the pin directory, and `PINS.log`, the lock and the kept copies are opened only as regular files: one that is not is a failure, `not-a-regular-file`, and the open itself refuses a link and does not wait (`O_NOFOLLOW`, `O_NONBLOCK`) where Node defines those flags, which it does not on Windows. A `PINS.log` with another name (its link count, from the file read, is above 1) is refused, `log-unreadable`. `PinRefusal.recordedRoot` gives the root PINS.log records, on `root-differs`.
- Library: a lock keeps two pins apart. A lock left by a process that no longer runs is taken over, and the lock is removed on SIGINT, SIGTERM and SIGHUP, including one that comes while the pin waits for the lock. A pin that stopped at any step of a write is recovered by the next one, with `recovered` lines in the log.
- Library: `checkPin` waits while a running pin holds the lock (up to `lockWaitMs`, 30 s by default; then `PinBusy`), then checks every version the log records against the copy that holds it (`PinMismatch.copy` names it), reading each copy once. It also checks the chain of the log's lines, and how far the pin is behind its sources: files missing from the pin (a `.jsonl` with no new line yet is not missing), or longer than their copy (a `.jsonl` whose copy is a byte prefix of it, longer only by an unfinished line, is counted apart, `PinStaleness.unfinished`). `PinCheckDone.logNames` is the link count of the `PINS.log` read; above 1, a notice says that a pin refuses it.
- docs/library.md describes every exported symbol and field of both entry points: its meaning, its unit, and when it is absent. It opens with the recipe the CLI uses: turnsOf(t) alone stops at the last compaction, giving 201 turns where ltms counts 218 on a demo project's 35 transcripts. It says what each entry point reads and returns, and the edges a crafted file reaches: `caller` is an object, a census key written as null is not counted, an empty timestamp is read in file order, TranscriptStats.inputTurns counts a prompt record without the envelope, and LineProblem.sample can end in the escaped first half of a cut surrogate pair.
- README: a Library section. Privacy now says that the library's parser returns the transcript's content, to which the command's output rules do not apply; that its search applies the label rule itself; and that pin's functions return paths, sizes, hashes and times.
- README: a section `ltms search <query> <path>...` (an example, every field, what is searched, the notice, reading a hit, the limits); What it reads and Privacy now say what search reads and prints.
- README: a section `ltms pin <path>... --to <dir>` (what it copies, the pin directory, the output, checking a pin, a `SessionEnd` hook, a cron line that sets `PATH`, the exit status, the limits); What it reads and Privacy say what pin reads and writes, and the Bash verb's table gains a command that ends in a dangling `&&`.
- npm test names its test files explicitly (a glob is not expanded under cmd.exe on Node 20), and no option that filters tests out. New tests check every import path against the packed tarball, every file exports and typesVersions name, package.json's files, TypeScript consumers under four module resolutions, the declarations against docs/library.md (each row's "when absent" against its member's declared type too), dist/ against the build, the README's recipe run as written against `ltms stats`, and the committed fixtures against make-fixtures.mjs's output.
- test/library.test.mjs: the value of every member the parser computes is asserted on known-answer fixtures, each worked out by hand. These are the 113 computed members of its result types, including the objects parseLines, livePath and repairedLivePath return. A member added to one of the parser's result types fails a test until its value is asserted; a member added to an object search or pin returns fails one until it is declared.
- test/make-fixtures.mjs: nine generators write the library's fixtures, test/fixtures/library-*.jsonl; every existing fixture is unchanged, byte for byte.
- Tests: `test/search.test.mjs`, 102 tests, and six synthetic fixtures (`search-*.jsonl`, written by `make-fixtures.mjs`). They cover every kind and everything not read, line by line; the turn rule against skeleton's turns on every fixture; the invariant on every fixture; the 120 known queries; a reference of the normalization compared on 6,000 seeded strings; offsets; the line reading against the whole field; the Segmenter check with Intl taken away; and the command: its options, refusals and messages, the coverage's counts, and the walk (a real bind mount where `unshare` can make one, and a stubbed `stat`). `test/cli.test.mjs` follows the new commands (the unknown-command message, the README's example lines, the import list), and its README test reads skeleton's rows from skeleton's section and stats' from stats'.

### Known limits (to be fixed in 0.1.1)

- A copy damaged so that its size changed and that is no prefix of its source, found by `--rehash` while its source cannot be read, is recorded as it is. When the source can be read again, the `--rehash` command that `--check` gives keeps those damaged bytes as the old copy of a rewrite, and `--check` then reports that version at every check, with no command. The current copy is written from the source: nothing the source still holds is lost.
- A file pinned by its own path under a `.git/` directory or under `memory/subagents/`, whose copy is then damaged: `--check` gives a `--rehash` command that changes nothing, at every check. Pinning that file by its own path with `--rehash` (`ltms pin <the file> --to <dir> --root <root> --rehash`) writes it again. The source is not touched: nothing it holds is lost.
- While `PINS.log` has a second name (a hard link), `--check` still says what the next pin records or removes, though every pin into the directory is refused until that name is gone; and the `find -samefile` command in its notice is not quoted for a path that holds a `'`: with one, the shell rejects it; with two, it searches a path that does not exist. No pin writes meanwhile: nothing is lost.
- A copy that holds its version followed by other bytes, its source unchanged: `--rehash` records those bytes and keeps them as the old copy of a rewrite, so `PINS.log` says `rewritten` though the source never changed. The current copy is written again from the source, and `--check` then passes: nothing is lost.

## 0.0.5

- The README has a new first section, Intent and tradeoffs: the intent of the design, its scope, and its objectives with the price of each.
- The README says that every call reads all of the context window again, where it said that every call re-sends it.
- The README says that `ok` is the status of the call as a whole: for a Bash command of several parts, the status the shell returned for the whole command (in `a; b`, that of `b`), so a part that failed before the last can read `true` (what it printed, if anything, is at the call's `r` address); and that for a command run in the background it is the status of its launch.
- Tests: the Bash verb at its limit (the program after 15 commands passed over, `(withheld)` after 16) for each separator the README names (a new line, `;`, `&&`) and each kind of command passed over (`cd DIR`, a command of assignments only); and the library's NUL repair, reachable only through its `repairNul` option, since the command does not set it (ltms skips a line holding NUL bytes and counts it on stderr).

## 0.0.4

- The name: the package is now `long-term-memory-structure`, published until 0.0.3 as `memobrain`. The command is `ltms`, and `npx long-term-memory-structure` runs it without installing. Messages on stderr start with `ltms` where they started with `memobrain` (`ltms skeleton: warning: ...`), and the usage text and `--help` name `ltms`. No output field changed. The repository is `long-term-memory-structure/long-term-memory-structure`; the test suite's variables are `LTMS_HEAVY` and `LTMS_CLI`.
- Library: a DETACHED compaction is joined. From CLI 2.1.295 the boundary and its summary are a two-node root branch, and the `/compact` command's own records (typed before the boundary, written after the summary) are parented around the pair, so the live path left both out. `repairedLivePath` now places the pair between the command and its output ("Compacted"), the order the events happened in, and reports the join in `compactions` with `via: 'detached'`. The skeleton's lines do not change: neither the boundary nor the summary is a turn or a call.

## 0.0.3

- Output changes, on crafted input only (on 2,539 real transcripts the output did not change, and neither did what the parser makes of them: the live path, its joins and repairs, requests, turns and counts):
  - a hook block names its script only where a command's script stands: the command itself, or the word right after an interpreter (`bash /x/gate.sh`), after any leading `env` and `NAME=value` words. Anywhere else the one word with a script extension may be an argument, and the class is a plain `hook-block` (`/h/guard /data/notes.py` named `notes`);
  - quotes and punctuation around a word no longer hide its script extension: a quoted hook and its argument give a plain `hook-block` (it named the argument), and a quoted hook alone is named;
  - a value that is not a string where a string belongs (a record's type, version, uuid or timestamp, a system record's subtype, an attachment's type, a block's type, a tool's name or id) is never turned into one, so it can no longer stop the file at JavaScript's limit on a string's length (eight routes in the parser did, and so did the label of a late-written record); in the library's counts such a key is `(not a string)`;
  - an assistant record with neither a `requestId` nor a string `message.id` joins the response of the record it hangs off, when that one had neither too, with a warning: a parallel call whose record is off the live path had dropped out of its turn;
  - thousands of compaction boundaries, or of records bridged in file order, are joined in linear time (20,000 boundaries took 31 seconds, and now take 0.4).
- New warnings on stderr: files in one run that share an address prefix, and records whose response was read from their parent links.
- An internal error is reported by its kind and, when it was raised in memobrain's own code, its file and line; never by its message, which could quote the transcript (a message running over several lines cannot pass a line of itself off as the place).
- Library: `stats.requestKeyGuessed` counts the assistant records whose response was read from parent links; `NOT_A_STRING` is exported; a call whose id is not a string has an empty `spillFileHint`.
- `--version` and `-v` work after a command, as `--help` does.
- The README says that Claude Code cuts a project folder's name at 200 characters.

## 0.0.2

- The README opens with why memobrain exists: compaction replaces the model's context with a summary, and the transcript on disk keeps every record.
- Output changes, on crafted input only (on 2,513 real transcripts the output did not change):
  - after `command` or `time`, a following `command` or `exec` is the shell's builtin, so the verb is the program after it (`command exec make` prints `make`; it printed `exec`);
  - `nice` with only its options after it prints `nice` (it printed `(withheld)`);
  - `time` right after the `time` keyword is the keyword again (`time time make` prints `make`);
  - a redirection right after a wrapper withholds the verb (`nohup >/dev/null make` printed `nohup`);
  - `env`'s assignments count toward the limit of 63 words before the program;
  - a hook block names its script only when exactly one word ends in a script extension, whatever the other word's characters;
  - a hook block whose bracketed command is longer than 300 characters is a `hook-block` (it was `other`);
  - a value too large to write as JSON prints `(too large)` in `in` and `out`, with a warning, where the file was dropped; three routes in the parser where such a value stopped the file are guarded too (crafted values can still stop a file through others);
  - a prompt's text block that is not a string counts as empty text;
  - the skeleton is written in chunks, so millions of call lines no longer pass JavaScript's string limit;
  - a `toString` or `valueOf` key written with escaped characters no longer stops the file.
- The README and `--help` define every value the output can hold.
